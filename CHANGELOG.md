## In the first release

Written by hand before releases were automated; everything below ships in the first beta.

### Fixed

- Fans sped up and stopped over and over when two copies of the app were running (for example one started from Xcode). The newest copy now asks the others to quit.
- Custom profiles were lost at the next launch once a rule, alert or the menu bar followed Hottest Memory Sensor or Memory Average, which couldn't be read back.
- A fan whose speed range can't be read is left to macOS instead of being driven towards 0 rpm.
- The helper could crash on a speed that isn't a number, a very large speed, or a fan index above 9. It now refuses such requests, as well as fans this Mac doesn't have and fans whose range can't be read, instead of writing an unclamped speed.
- After a crash, the helper now returns every fan to automatic as soon as it starts again, instead of leaving it at its last speed.

### Security

- Release builds of the helper refuse debuggable (`get-task-allow`) clients, and Release builds of the app are signed without it.
- CI pins its actions to commit SHAs and SwiftFormat to a checksummed release, Dependabot waits 7 days before proposing a new release, and a Semgrep job checks the helper against the project's own rules in `.semgrep/`.
- A copy that isn't signed by a developer team, such as the downloadable release, no longer asks to install the helper, which would refuse it anyway. It explains that fan control needs a build from source.

### Added

- Read fan speeds and ranges from the SMC.
- Read CPU, GPU, battery, Wi-Fi and trackpad temperatures, with a sensor map for M1 Pro and M1 Max.
- Read SSD, Battery Gas Gauge and Power Manager Die Average temperatures from IOHID sensors. The SSD appears under Disk Drives with its model name.
- Memory (own group), Airflow Left/Right, Charger and Battery 1–2 temperatures, named after Stats and Asahi Linux.
- Rename profiles in place from the sidebar's context menu or Fans › Rename Profile.
- Custom rules can follow several sensors at once and use the hottest, chosen in one Sensors menu.
- Hysteresis for Custom rules: the fan slows down only after the temperature has fallen by a set amount (3 °C by default).
- Drag the corners of the fan curve to change its temperatures; the current reading follows while dragging.
- Export and import profiles as JSON files.
- Temperature alerts (sidebar › Automation › Alerts): a notification when a sensor goes above a limit, repeated only after it has cooled 5 °C below it.
- Automatic profile switching (sidebar › Automation › Profile Switching): on battery, on the power adapter, or while an app is open.
- Main window with a sidebar (fans, temperatures, profiles) and a detail view, and a live fan curve chart for Custom rules.
- Temperatures turn gradually red between each sensor's warm and critical limits, with a warning symbol at the critical limit (Temperatures page and menu bar panel).
- A dot next to Temperatures in the sidebar appears once any sensor is warm, redder as the hottest sensor nears its limit, or when macOS reports a raised thermal state.
- macOS's own thermal state (Normal, Fair, Serious, Critical) at the top of the Temperatures page and in the menu bar panel.
- Temperatures table: sortable, with a symbol per sensor, grouped by component (CPU, GPU, Other Sensors, with averages) or as one list via View › Group by Component.
- Menu bar extra showing the hottest CPU temperature next to the fan symbol. Clicking it opens a panel in the style of the system's own, with live fan gauges, temperature tiles and the profile list.
- Settings › General: temperature unit (Automatic, Celsius or Fahrenheit; Automatic follows the system), language (System, English, Türkçe; applies after a restart offered in place), show icon in Dock, and open at login. The Dock icon and the menu bar item can't both be hidden.
- Settings › Menu Bar: show or hide the menu bar item and its icon, choose the temperature it shows (hottest CPU core, CPU core average, hottest GPU cluster, GPU cluster average or any single sensor), and show the speed of one or both fans.
- Standard About window with links to furkansenturk.com and the GitHub repository.
- App icon: a custom five-blade fan on a blue gradient, made with Icon Composer layers so macOS 26 renders it in Liquid Glass. The same fan, as a template image, is the menu bar icon.
- English and Turkish localization.
- `smc-dump` diagnostic tool and `Scripts/dump-sensors.sh`.
- Fan profiles: built-in Automatic (default), Full Speed and Custom, plus your own profiles that you can create, duplicate, rename and delete. Changing a fan on its own page switches to Custom, which can be saved as a new profile. Pick a profile in the sidebar, the Fans menu or the menu bar extra.
- Automatic / Manual / Custom control per fan. Manual holds a constant speed; Custom follows a temperature (any sensor, the hottest CPU core or GPU cluster, or the CPU or GPU average) between a start and a maximum temperature.
- Privileged helper (`FanHelper`), installed with `SMAppService` and reached over code-signature-checked XPC. It returns fans to automatic when the app quits.
- Inline prompt to allow the helper in System Settings › Login Items.
- **Fans › Set All Fans to Automatic** (⌥⌘A) switches to the Automatic profile.
- Settings › Fan Control pane: helper status, a live connection check, and Open Login Items, Reinstall and Remove actions. Fan error messages link straight to it.
- XPC calls time out after 5 seconds, so a helper that can't launch is reported instead of hanging.
- After an update the app restarts an outdated helper, so the new helper runs without a restart or a new approval.
